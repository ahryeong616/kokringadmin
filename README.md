# 현장 시세조사

매장을 돌며 가격표·라벨을 찍어 기록하고, 같은 상품을 매장별로 비교하는 앱입니다.

> **재고관리(콕링 재고관리)와 완전히 별개인 앱입니다.**
> 저장소는 같지만 이 앱은 `survey` 브랜치에만 있습니다. 재고관리는 `main` 브랜치를 보므로
> 서로 영향을 주지 않습니다. Railway 에서도 **각각 다른 서비스**로 띄웁니다.

## Railway 배포

**주의 — 반드시 새 서비스로 만드세요. 기존 재고관리 서비스를 고치면 안 됩니다.**

1. Railway → **New Project** → **Deploy from GitHub repo** → `kokringadmin` 선택
2. 만들어진 서비스 → **Settings** → **Source** → **Branch 를 `survey` 로 변경** ← 가장 중요
3. 같은 프로젝트 안에 **New → Database → Add MySQL**
4. 서비스 → **Variables** 에 두 개를 넣습니다

   | 이름 | 값 |
   |---|---|
   | `DATABASE_URL` | `${{MySQL.MYSQL_PRIVATE_URL}}` (값 칸에 `${{` 입력 후 목록에서 선택) |
   | `APP_ACCESS_KEY` | 직접 정하는 접속 비밀번호 |

5. **Deploy** 클릭 (변수는 Deploy 를 눌러야 반영됩니다)
6. **Settings → Networking → Generate Domain**

## 쓰는 법

1. 만들어진 주소를 폰·PC 에서 엽니다
2. 아래 **내보내기** 탭 → **기기 간 동기화** 에 `APP_ACCESS_KEY` 를 넣고 **동기화 켜기**
3. 같은 주소·같은 비밀번호를 쓰는 기기끼리 기록이 서로 맞춰집니다

## 동작 방식

- 기록은 **기기(IndexedDB)에 먼저** 저장됩니다. 창고에서 신호가 없어도 조사가 끊기지 않고,
  연결되면 알아서 올라갑니다.
- 다른 기기가 바꾸면 서버가 곧바로 알려 줍니다(화면이 저절로 갱신됩니다).
- 같은 기록을 두 기기에서 고쳤다면 **나중에 고친 쪽**이 남습니다.
- **사진·동영상은 기기에만** 남습니다(용량 때문). 글자 정보만 서로 맞춥니다.

## 문제가 생기면

주소 뒤에 `/healthz` 를 붙여 열면 현재 상태를 알려 줍니다.

| 보이는 것 | 뜻 |
|---|---|
| `{"ok":true,"db":true,...}` | 정상 |
| `DATABASE_URL 이 설정되지 않았습니다` | 4번 변수를 안 넣음 |
| `데이터베이스에 연결하지 못했습니다` | MySQL 이 다른 프로젝트에 있거나 준비 중 |

웹 화면은 데이터베이스와 무관하게 항상 열리도록 만들었습니다.
무응답(`Application failed to respond`)이 나오면 그건 다른 문제입니다.
